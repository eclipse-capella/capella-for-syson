== Capella GraphQL contributions

The application GraphQL endpoint is `/api/graphql`.
{product} contributes the following representation-related operations:

[cols="2,3",options="header"]
|===
|Operation or field |Purpose

|`createCapellaRepresentation`
|Create a representation using a Capella representation description.
The input identifies the editing context and representation description.

|`RepresentationMetadata.diagramFilters`
|Read the Capella filters associated with a representation, including their labels and state.

|`setDiagramFilterState`
|Enable or disable a filter for a specified representation.

|`saveCapellaDDVDiagram`
|Save a contextual view diagram, such as the Functional Context Diagram, as a project representation.
|===

== Example: change a diagram filter

The frontend's `useSetDiagramFilterState.ts` hook sends this mutation:

[source,graphql]
----
mutation setDiagramFilterStateMutation($input: SetDiagramFilterStateInput!) {
  setDiagramFilterState(input: $input) {
    __typename
    ... on SetDiagramFilterStateSuccessPayload {
      active
    }
    ... on ErrorPayload {
      messages {
        body
        level
      }
    }
  }
}
----

Supply `id` to identify the request, `editingContextId`, `representationId`, `filterId`, and the requested `active` state in the input.
Read the filter IDs from the representation's `diagramFilters` metadata.
The payload is a union: inspect `__typename` and handle `ErrorPayload` as well as the success payload, using the deployed schema for the error fields.
The request uses the same authentication and project access rules as the application.
