= Capella-Web Functional Test Inventory
:toc:
:toclevels: 3

This document lists candidate functional tests to add in `capella-web`.

== Baseline (2026-04-13)

- Existing backend tests are mostly architecture/coding-rule checks.
- Real functional backend tests currently contain one integration test class:
  `backend/application/capella-application/src/test/java/org/eclipse/capella/application/controllers/projects/ProjectControllerIntegrationTests.java`.
- Existing Capella-specific GraphQL schemas to cover:
  - `capella-create-representation.graphqls`
  - `capella-diagrams.graphqls`
  - `capella-ddv.graphqls`
- No frontend unit tests (`*.test.ts(x)` / `*.spec.ts(x)`) are currently present.
- No Cypress or Playwright suite is currently present in this repository.

== Notes for Implementation

- Prefer deterministic backend integration tests first for Capella-specific GraphQL and server-side behavior.
- Keep business-service unit tests in the corresponding module (`src/test/java`) and use real SysML fixtures over heavy mocking.
- For e2e tests, create/delete project test data in `beforeEach`/`afterEach` and rely on stable selectors (`data-testid`) where available.
- If adding a new e2e framework folder, keep helper/page-object layers from day one to avoid scenario duplication.
